# CBA-002 results — 0.2.0

Overall mission: **PARTIAL**. The central classic-CBH and multi-engine workflow is implemented and verified. CTG, Scid and ChessBase archive integrations are unfinished; those formats remain unsupported. No clean external Windows machine or full million-game position-index run is claimed.

## Actual CBH corpus

Windows' resolved Documents location identified the supplied multi-file collection. Exact path, per-game metadata/PGNs, error IDs and source hashes are private local evidence and are not published. The native header scan reports **11,743,083 records**, of which **11,741,260 are eligible non-deleted game records**. This is a source-header count, not a claim that all eligible games have been decoded.

The deterministic sample decoded **106 requested game records** with no unexpected failures. Two additional requested records were correctly reported as text. Coverage included the first actual game, middle/late records, seeded random IDs, annotated games, a game with variations and a nonstandard starting position. Every non-null decoded move in those trees was checked with python-chess. Native header fields were compared with PGN metadata, allowing only documented presentation conversions. Source annotation nulls are retained for analysis/replay; they are never returned as playable historical moves.

A **2,000-record** index segment cached **1,996 games**, produced **96,896 distinct positions** and **117,217 continuation rows**, and took **70.991 seconds** on this host. The SQLite file measured **26,894,336 bytes** at the recorded checkpoint. **145 analysis-null-mainline diagnostics** were retained: those PGNs remain available but their mainlines do not contribute historical move statistics. No decoder error was silently discarded. These numbers describe one early segment, not the entire collection or a universal throughput estimate. A native player-prefix header search scanned **11,743,083 records** in approximately **0.356 seconds**, finding **5,034 matching records** on that measured, potentially warm-cache run. Index construction and header search are different operations.

See `evidence/cba002-mega-benchmark.json` and `evidence/native-search-benchmark.json`. Full indexing would require substantially more time and storage; no full-index throughput is inferred as measured fact. The UI's next-segment estimate is 20 KB/record plus free-space reserve, and another cache drive can be selected.

## Application and engine verification

The packaged application opened the actual CBH source, displayed the native game count, built a bounded segment, accepted legal human moves, selected historical replies with actual recorded frequencies, and saved the game. A separate packaged process reopened the persistent catalog and replayed the saved game. Exact final installed receipts/screenshots are under `evidence/cba002-production-installed*` and `evidence/cba002-production-reopened*`; earlier portable integration receipts are under `evidence/cba002-mega-packaged*` and `evidence/cba002-mega-reopened*`; the receipt reports its actual indexed subset and frequencies. This is automated execution of the real Qt controller/widgets and native subprocess, combined with separate Qt mouse-move/promotion tests, not a manual operator clickthrough.

Stockfish 19 and official Lc0 0.32.1 CPU/OpenBLAS both completed UCI negotiation and returned legal moves. Lc0 used the network supplied in the official CPU archive. GPU acceleration was not tested or inferred. Both are registered in this user's application engine directory/catalog; engine binaries and weights are not part of the application installer. The engine-manager GUI is exercised separately, and engine-vs-engine play has an automated Qt test. Existing engine configurations and original engine installations are retained.

The complete test suite retains all 34 original tests and adds native data, framing, validation, recovery, engine/profile and GUI coverage. The machine-readable final counts are in `evidence/cba002-test-summary.json`; packaging and installation receipts are separate workflows rather than extra unit-test cases. Earlier integration findings included command-end framing, null analysis markers, native/PGN presentation normalization and a QDialog signal-name collision. Regression tests/validation cover the repaired behavior. Future-Python asyncio deprecation warnings remain dependency warnings, not hidden failures.

## Remaining limits

CTG/CTB/CTO, Scid and CBV/CBZ lack integrated, real-file-tested CBA adapters. ABK is partial with generated-file evidence; 2CBH is partial with no representative local real-file acceptance. XBoard is not integrated. Native global player search currently supports classic CBH player-prefix and optional year; indexed move filters support player/event/year/Elo/result/opening. Broad query results are bounded, move statistics cover committed subsets, and source-specific comparisons do not pretend overlapping corpora are disjoint. Clocks remain basic without increment. No broad Unicode-name corpus, GPU, accessibility, display/DPI matrix, code-signing or clean external-machine certification is claimed.

Installation evidence distinguishes an isolated-AppId test install/uninstall (original registration preserved) from the production installer upgrade. The production installed executable is compared with the portable executable by SHA-256. Existing user catalog/settings files are hashed before and after the upgrade and remain unchanged. Full source hashes cover all 29 discovered original database files. Neither test is a clean external Windows-machine certification.
