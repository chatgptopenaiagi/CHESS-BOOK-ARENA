# CBA-002 native reader architecture

The existing app, catalogs and saved-game schema are extended with additive tables (`native_state`, `native_games`, `decode_errors`, `book_moves`). Original sources remain separate from derived indexes. Existing saved-game rows are preserved.

`app/database_readers` defines explicit capabilities, logical companion discovery, standard reader adapters, native CBH/2CBH adapter and guarded ABK traversal. CBA owns `native/arena-reader`, a small JSON-lines executable linked to pinned cbvault; the upstream source is fetched separately by `scripts/Build-Native.ps1`, never edited in place. Rust libraries cannot be imported as Python modules. The packaged helper is discovered relative to PyInstaller's runtime root and communicates only through pipes.

One helper maps one source set read only. Commands include counts, random-access game retrieval, bounded record ranges and classic-CBH player-prefix header search. Responses retain stable source IDs, skip reasons for text/deleted records, native header fields and annotated PGN. Python drains each command's end marker before another request; this contract has a regression test. Queue buffering is bounded to 64 records. Timeouts and process exit become meaningful errors, and cancelled ranges terminate their helper. Python validates every non-null decoded variation move; null markers in analysis are preserved, not offered as chess moves.

Native header fields are compared with parsed PGN headers. The adapter permits only documented PGN presentation changes: empty fields to `?`, figurines to piece letters, and a terminal period on one/two-character uppercase/digit player initials. Other disagreements are recorded as errors. The PGN preserves comments/variations; canonical index rows include mainlines only. Analysis-only null mainlines are cached for replay with a diagnostic, and excluded from historical statistics.

Each committed record advances a SQLite checkpoint. Cancel leaves committed data intact. Source component names/sizes/nanosecond timestamps invalidate stale indexes; separate SHA-256 source checks verify the acceptance exercise. Per-source error IDs remain local and can be queried from `decode_errors`. Derived data can be moved to a user-selected drive using a SQLite backup, preserving the previous catalog. The index-segment dialog estimates 20 KB per record and checks free space before work; this is an estimate, not a guaranteed bound for arbitrarily large annotated games.

Position queries operate only on the committed subset, and the UI identifies that scope. A direct header search can cover all 11.7 million source records without first indexing their moves. Its player-prefix criterion is constrained to avoid unconstrained result materialization. The GUI can fetch an arbitrary native record even if its position rows have never been indexed.

The separate engine manager persists verified UCI identity/options, profile settings and default choice. Its known-location discovery probes only plausible engine names from trusted/user-selected locations; a GUI executable is not an engine candidate. READY means the UCI handshake passed, not that every backend, optional network or GPU configuration has been tested. Stockfish and an official Lc0 CPU package were separately exercised for legal play. Downloads are allowlisted to official release repositories, bounded, path-checked, checksum-checked when a release digest exists, PE-x64 checked and UCI-verified before registration. Engines remain optional and external to the installer.
